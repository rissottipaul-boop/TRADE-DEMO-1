# Команда агентов и передача работы

Дата проверки: 2026-09-30. Статус: внедрены реестр, выбор моделей и передача через доску; совместимость guard новых клиентов требует отдельной проверки.

Регламент — [AGENTS.md](../AGENTS.md), работа — [board.md](board.md), роли — [.github/agents/](../.github/agents/). [agent-routing.json](agent-routing.json) задаёт порядок и модели для [agent-rotate.ps1](agent-rotate.ps1). Он не меняет права, риск-лимиты, аккаунты и расписания.

## Назначения

Первым указан основной исполнитель, далее замены слева направо. Назначение учитывает специализацию и уже работающую инфраструктуру проекта; сравнения на собственном наборе задач пока нет. Выбор сильной модели не гарантирует правильность результата — приёмка остаётся обязательной.

| Роль | Основной исполнитель | Замены при недоступности | Критерий профессиональной работы |
| --- | --- | --- | --- |
| Project Orchestrator | Claude / `opus` | Codex / `gpt-6-astra` → Gemini / `pro` → Muse / `muse-spark-1.3` | Зависимости, claims, делегирование, приёмка по критерию доски; один координатор задачи |
| Insight Executor | Codex / `gpt-6-astra` | Claude / `opus` → Gemini / `pro` → Muse / `muse-spark-1.3` | Код, отладка, тесты, минимальный diff, сохранение чужих изменений |
| Crypto Insight Hunter | Gemini / `pro` | Claude / `opus` → Codex / `gpt-6-astra` → Muse / `muse-spark-1.3` | Первичные источники, проверка фактов, воспроизводимость, явные неопределённости |
| OKX Trader | Claude / `opus` | Codex / `gpt-6-astra` → Gemini / `pro` → Muse / `muse-spark-1.3` | Проверенные инструменты, риск-лимиты, clOrdId, сверка результата; резерв до проверки guard только анализирует |
| Pump Risk Taker | Claude / `opus` | Codex / `gpt-6-astra` → Gemini / `pro` → Muse / `muse-spark-1.3` | Фиксированный сканер, карман и стоп; модель не придумывает новые лимиты |
| Ops Sentinel | Claude / `sonnet` | Codex / `gpt-6-sol` → Muse / `muse-spark-1.3` → Gemini / `pro` | Регулярный чек-лист и журнал; сложный инцидент передаётся Opus/Astra |

Это целевое распределение ролей. **Операционная готовность ниже модельного приоритета:** новый Codex CLI запускается в read-only, ролевые Gemini/Muse получают ограничение на анализ до проверки hook. Через них нельзя автоматически подменять действующего торгового исполнителя. Текущая Codex-сессия выполняет прямые инженерные поручения по регламенту; её инструменты и permissions определяет хост приложения, launcher не меняет уже открытые сессии.

Для ограниченных задач без риска допускается явный выбор: Claude `sonnet` для обычных исправлений, Codex `gpt-6-sol` для исполнения, `gpt-6-luna` для извлечения/сводок, Gemini `flash` для краткой обработки источников. Автоматического понижения качества при квоте нет. `gpt-6.1-sol` документирован как новый вариант для длительной работы, но не закреплён по умолчанию без проверки доступа аккаунта. Доступность моделей и тарифы не проверялись запросами к аккаунтам.

Пять обёрток [.claude/agents/](../.claude/agents/) содержат `model`, совпадающий с реестром: `opus`, кроме `ops-sentinel` (`sonnet`). Это применяется к новым субагентам Claude. Модель основной сессии задаёт launcher с `-Role`; уже открытая сессия сохраняет свой выбор. У Codex/Google/Meta ролевые промпты читают канонический файл, без копирования его текста. Флаг модели родительского CLI не гарантирует ту же модель у его внутренних субагентов: каждый дочерний запуск должен учитывать эту таблицу и возможности своего клиента.

## Использование

```powershell
# Только план, без модели, сетевых вызовов и записи журнала
ops\agent-rotate.ps1 -Role insight-executor -Plan
ops\agent-rotate.ps1 -Role crypto-insight-hunter -Plan

# Codex: чтение и разбор конкретной задачи
ops\agent-rotate.ps1 -Agent codex -Role insight-executor -TaskId T42 -Prompt "Проверь diff и предложи исправление"

# Передача после квоты: сначала записать handoff и завершить прежний процесс
ops\agent-rotate.ps1 -Role insight-executor -SkipAgent codex -TaskId T42 -Plan
# Убрать -Plan для запуска выбранного преемника

# Явная модель для ограниченной задачи; модель не меняет права
ops\agent-rotate.ps1 -Agent claude -Role insight-executor -Model sonnet -TaskId T42 -Plan

# Headless с фиксированной задачей, а не второй бесконечный автопилот
ops\agent-rotate.ps1 -Agent claude -Role insight-executor -Headless -TaskId T42 -Prompt "Продолжи по handoff из доски"
```

`-SkipAgent` принимает массив; несколько рантаймов в PowerShell: `-SkipAgent @('codex','claude')`. Скрипт не угадывает остатки подписок. Исключения действуют только на этот запуск. После восстановления квоты можно снова выбирать основной рантайм. Модели одного провайдера могут делить общий лимит, поэтому для квоты сначала выбираем другого провайдера.

Без `-Role` сохранён порядок Claude → Gemini → Muse, затем Codex; модели первых трёх наследуются из их настроек. `-Agent antigravity` сохранён как псевдоним `gemini`; `agy` больше не подменяет его молча. Antigravity запускается отдельно с его собственными настройками. Наличие `ops/muse.cmd` означает только наличие WSL-обёртки, а не работоспособность Muse внутри WSL. В JSON-плане это видно как `wrapper_unverified`.

Интерактивный Claude запускается интерактивно; `-Headless` использует `--print`. Gemini headless использует `--prompt`, а не неподтверждённую команду `exec`. Codex headless использует `exec`. После старта **нет автоматического повторения промпта**, даже при ненулевом коде: процесс мог уже изменить файлы или выставить ордер. Его код возвращается вызывающему процессу; stdout проходит сразу, чтобы TUI не зависал в буфере. Журнал `logs/agent-rotate.log` содержит метаданные старта/завершения без текста задания и ответа модели.

## Передача без конфликтов

1. Прежний исполнитель сохраняет в заметках **той же задачи**: роль, рантайм и фактическую модель, файлы, выполненные шаги, точные проверки и результаты, незавершённые действия/ID, следующий безопасный шаг, причину передачи и известное время сброса лимита.
2. Он прекращает работу над файлами и возвращает задачу в `ready` с пометкой передачи. Не создавать вторую строку для той же работы. Нельзя выбирать другой рантайм, чтобы обойти отказ guard.
3. Преемник читает регламент, каноническую роль, текущую доску (допустимо адресно: `.venv/Scripts/python.exe -m src.agent_context --task <ID>`) и handoff; проверяет git diff и свежесть файлов, затем ставит свой claim. Независимые задачи делегируются только с непересекающимися файлами.
4. Если предыдущая сессия оборвалась, сначала восстановить результат из файлов/журналов. Для запроса к бирже с неизвестным результатом сверить ordId/clOrdId/algoId; без сверки повтор запрещён. Когда состояние нельзя установить — `blocked`, а не повтор «с нуля».

Пример заметки: `Передача: Insight Executor / Codex / gpt-6-astra; квота до <время или неизвестно>; файлы ...; сделано ...; проверено <команда, результат>; не завершено ...; внешние действия/ID ...; следующий шаг ...; процесс завершён.`

## Экономия контекста

Правила и замеры — [token-economy.md](token-economy.md). Экономия не меняет таблицу назначений: модель, reasoning, объём проверок, риск-лимиты и частоту мониторинга ради неё не снижают. С `-TaskId` launcher сам добавляет в промпт адресное чтение карточки через `src.agent_context`; без `-TaskId` агент начинает с обзора той же командой или с полной доски. Мелкие механические подзадачи (тесты по спецификации, замеры, сверки) можно отдать Muse через мост [delegations/README.md](delegations/README.md); приёмку по критерию доски делает постановщик.

## Границы текущей интеграции

- Codex CLI найден: `0.155.0-alpha.16.3`. `AGENTS.md` подхватывается штатно. Его размер после правок проверяется относительно стандартного лимита 32 KiB. Отдельный `AGENTS.override.md`, Stop-autopilot, глобальный конфиг и авторизация не создаются.
- Общий guard читает `tool_input.command`. Codex `exec_command` передаёт `cmd`; `functions.exec` может содержать вложенные вызовы. Простое подключение прежнего файла как hook не доказывает защиту. Нужен адаптер форматов с тестами неизвестных оболочек и проверкой реального отказа в клиенте. Read-only sandbox ограничивает файловые записи shell, но не является торговым guard для подключённых MCP.
- В Gemini настроен `PreToolUse`, а документирован `BeforeTool`; единица timeout — миллисекунды. Нужна проверка схемы входа и ответа, не только переименование события. Установленный Gemini CLI 0.62.0 подтверждает флаги модели/headless; ролевой launcher дополнительно задаёт `--approval-mode plan`.
- Muse использует существующую обёртку Windows → WSL. Hook с `.venv\\Scripts\\python.exe` и доверие к workspace внутри WSL не проверены. Загрузка project `.muse/settings.json` в имеющемся формате не подтверждена; явный `--model` снимает зависимость назначения модели от этого файла.
- Настройки hooks всех существующих клиентов, `ops/hooks/`, `ops/autopilot.json`, торговый код, движок и расписания этой интеграцией не меняются. Проверка launcher выполняется на подставных CLI, без запуска дополнительных торговых сессий. Испытание guard в клиентах выделено на доске; менять защищённые настройки можно только по §2 регламента.
- 30.09 (AGENT-GUARD-COMPAT): несовместимости подтверждены по установленным пакетам и документации — Gemini пропускает `PreToolUse` и не понимает ответ guard, Codex передаёт патч в `command`, hook Muse в WSL падает с exit 127, а в untrusted-режиме моста не грузится вовсе. Адаптер, патч и сценарий E2E — [guard-compat.md](../insights/guard-compat.md); применение — GUARD-COMPAT-APPLY (человек).

## Основания выбора и интерфейсов

- [OpenAI: модели Codex](https://learn.chatgpt.com/docs/models) и [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra): Astra — сложные задачи, Sol — длительная инженерная работа, Luna — ограниченные повторяемые задачи. Это описание поставщика, не независимый рейтинг между провайдерами.
- [OpenAI: AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [hooks](https://learn.chatgpt.com/docs/hooks) и локальные `codex --help`, `codex exec --help`: автоматические инструкции и параметры launcher. Hook требует отдельной проверки trust/протокола.
- [Claude: модели](https://code.claude.com/docs/en/model-config), [субагенты](https://code.claude.com/docs/en/sub-agents), [CLI](https://code.claude.com/docs/en/cli-reference): алиасы `opus`/`sonnet`, поле `model`, headless `--print`.
- [Gemini: модели](https://geminicli.com/docs/cli/model/), [CLI](https://geminicli.com/docs/cli/cli-reference/), [hooks](https://geminicli.com/docs/hooks/reference/); [Antigravity headless](https://antigravity.google/docs/cli/headless/): отдельные клиенты, подтверждённые флаги и события.
- [Meta: модели](https://dev.meta.ai/docs/overview), [Muse Spark 1.3](https://research.meta.ai/blog/introducing-muse-spark-1-3), [настройки CLI](https://dev.meta.ai/docs/muse-code/configuration), [hooks](https://dev.meta.ai/docs/muse-code/extending): ID модели и интерфейсы. Наличие опубликованного ID не подтверждает доступ в конкретной подписке.

Следующая оценка распределения: одинаковые 5–10 безопасных задач на фейках/исторических данных; учитывать выполненный критерий, пропущенные дефекты, нарушения регламента, время и стоимость. Критические ошибки безопасности исключают рантайм из торгового резерва независимо от скорости.
