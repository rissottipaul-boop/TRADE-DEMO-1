# Контур — локальная панель проекта

Старт из корня проекта:

```powershell
.venv\Scripts\python.exe -m src.control_panel
```

Команда печатает ссылку с временным токеном. Откройте её в браузере на этом компьютере. По умолчанию панель слушает `127.0.0.1:8765`; `--port 0` выбирает свободный порт. Остановить панель — `Ctrl+C`. Токен меняется при каждом запуске, не записывается в файл и не выводится в access log.

## Что показывает

- Все строки `ops/board.md` с поиском и фильтрами; дубликаты ID отмечаются. По клику на ID открывается полный критерий, зависимости и заметки. Число доступных задач учитывает выполненные зависимости и неоднозначные ID. Панель не меняет доску и не переносит решения человека.
- Рантаймы и назначенные модели из `ops/agent-routing.json`; события запуска из `logs/agent-rotate.log`.
- В карточке задачи можно получить план `agent-rotate.ps1 -Plan`: выбранный рантайм, доступность CLI, модель и состояние guard. Этот просмотр не создаёт run, claim или запись в журнале ротации.
- Кнопка «Сформировать пакет» создаёт текст для передачи задачи другому рантайму: полная строка доски, зависимости, все активные claims, SHA256 доски, Git HEAD/ветка/имена изменений и записи ротации с тем же ID задачи. Пакет создаётся на момент запроса и копируется через буфер обмена; типичные значения ключей и токенов скрываются. Он не создаёт claim и не заменяет новый SYNC, сверку Git и внешних действий.
- Состояние движка через `src.engine_watchdog` и риск через существующий `src.obsidian_status.build_snapshot`.
- Очередь Muse: последние заявки `inbox`, `processing` и `outbox` с фильтром стадий, ID, ролью, источником и путём записи. `processing` означает только наличие файла, а не доказанный живой процесс; стоимость помечена как неизвестная. Prompt, ошибки и вывод модели не передаются в браузер.
- Известные PID-файлы движка, live-runner и Muse, а также `git worktree list`. Для PID-файлов показано наличие процесса; владельца подтверждает только профильная ops-команда.
- Короткие хвосты логов движка и делегирования.

Обновление — каждые 10 секунд. Часть данных может быть недоступна, если соответствующий файл ещё не создан; остальные разделы продолжат работать.

## Кнопки

Разрешены `engine.start`, `engine.stop`, `delegation.pause`, `delegation.stop`. Движком и раннером управляют уже существующие `ops/engine.ps1` и `ops/delegate.ps1`; панель не завершает процессы по PID сама. Каждое действие требует подтверждения в браузере. `delegation.pause` создаёт `ops/delegations/PAUSED` и не удаляет заявки.

Результат каждого HTTP-действия записывается в `logs/control-panel-actions.jsonl` без токена, prompt и вывода команды.

Запуск агентских CLI, возобновление очереди, reset блокировок и торговые операции в HTTP API отсутствуют. Перед добавлением управления agent run нужны проверка guard по `GUARD-COMPAT-APPLY`, идентификаторы сессий, подтверждённые `steer/cancel` и тесты восстановления. Текущие capabilities описаны в [архитектуре](../agent-control-plane.md).

## HTTP

- `GET /health` — минимальный статус сервера.
- `GET /api/state` — агрегированный снимок, заголовок `X-Control-Token`.
- `GET /api/task?id=ID` — полная карточка; дубликаты ID отклоняются.
- `GET /api/handoff?id=ID` — снимок передачи и Markdown для копирования; токен обязателен, дубликаты ID отклоняются. Читает доску, `git status` и журнал ротации, не читает `.env` или содержимое diff.
- `POST /api/agent/plan` — JSON `{"task_id":"ID","role":"insight-executor","agent":"auto"}`; вызывает только `-Plan`, возвращает отфильтрованный результат без prompt и CLI-аргументов.
- `POST /api/action` — JSON `{"action":"engine.stop"}` и тот же заголовок.

Сервер принимает только `Host: 127.0.0.1:<порт>`, проверяет `Origin` для POST, ограничивает размер тела запроса и допускает только перечисленные действия. Панель предназначена для доверенного локального компьютера. Не публикуйте порт через reverse proxy: для сетевого доступа нужны отдельная аутентификация и TLS.
