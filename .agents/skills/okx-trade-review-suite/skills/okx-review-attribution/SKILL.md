# 交易盈亏归因分析 — 一键拆解赚钱主力与亏损黑洞

**解决一句话问题**：我这段时间的 PnL，是被哪个币、哪个方向、哪个时段贡献出来的？

只读复盘 Skill，不下任何单。基于账户已实现持仓历史（positions-history）与账单流水（bills），把总 PnL 按多维度拆成瀑布图，让你看清：真正赚钱的是哪几笔、亏损集中在哪里、是否存在"一币盖全场"的集中度风险。

## ⚙️ 可配置参数

首次使用时逐项确认或说"用默认"跳过。

### 复盘参数

| 参数 | 默认值 | 可选范围 | 说明 |
|------|--------|----------|------|
| 时间窗 | 最近 30 天 | 7d / 30d / 90d / 自定义起止 | 分析窗口 |
| 品种过滤 | 全部 | 全部 / 指定 instId 列表 | 例 `BTC-USDT-SWAP,ETH-USDT-SWAP` |
| 账户类型 | SWAP+FUTURES+SPOT | SPOT / SWAP / FUTURES / OPTION / ALL | 归因按合约类型过滤 |
| 分桶维度 | 币种+方向+时段 | 币种 / 方向 / 时段 / 杠杆 / 全部 | 可多选 |
| Top N | 5 | 3-20 | 币种贡献榜只展示前 N |
| 噪声阈值 | ±0.5% | 0-5% | 贡献占比低于此值归入"其他"折叠 |
| 时段切分 | 日内/隔夜/周末 | 日内(<6h) / 隔夜(6-24h) / 超隔夜(>24h) / 周末 | 按持仓时长 |
| 货币单位 | USDT | USDT / USD | 显示口径 |

### 数据健康参数

| 参数 | 默认值 | 可选范围 | 说明 |
|------|--------|----------|------|
| 采样覆盖率红线 | 80% | 50%-95% | 低于此值拒绝出报告 |
| 归档自动切换 | 开启 | 开启/关闭 | 超 7 天自动加 `--archive` |
| API 重试次数 | 3 | 1-5 | 失败重试上限 |
| 单次拉取上限 | 500 笔 | 100-1000 | positions-history --limit |

## 🔐 凭证与 Profile 校验（必跑，每次）

### Step A — 凭证检查

```bash
okx config show      # 验证配置（输出已脱敏）
```

- 无配置 / 报错 → **停止一切操作**，引导用户跑 `okx config init`
- 有配置 → 进 Step B

### Step B — Profile 确认（必填）

`--profile` 对所有鉴权命令强制必填。只有两个值：

| 值 | 模式 | 资金 |
|---|---|---|
| `live` | 实盘 | 真实资金 |
| `demo` | 模拟盘 | 模拟资金 |

**决策规则**：
1. 用户当前消息有明确意图（"实盘"/"live"/"真仓" → `live`；"模拟"/"demo"/"测试" → `demo`）→ 使用并告知："使用 --profile live（实盘）"
2. 当前消息未声明 → 查上下文是否已有 profile：
   - 有 → 继续使用，告知："沿用之前的 --profile live"
   - 无 → 问 "live（实盘）还是 demo（模拟盘）？"，**等回答再继续**

### 401 认证失败

若任何命令返回 401：
1. **立即停止**，不要重试
2. 告知用户："鉴权失败（401），API Key 可能过期或无效"
3. 引导用户本地编辑 `~/.okx/config.toml` 更新 `api_key / secret_key / passphrase`（**不要让用户把密钥粘到对话里**）
4. 跑 `okx config show` 验证
5. 才可重试原命令

## 🔁 核心流程

### 第一步：拉取原始数据

**已实现持仓历史**（PnL 主数据源）：

```bash
okx --profile <live|demo> account positions-history \
  --instType SWAP \
  --begin <开始时间戳ms> --end <结束时间戳ms> \
  --limit 500 \
  --json
```

> 超 7 天的数据需加 `--archive`；若用户时间窗 >7 天且默认"归档自动切换=开启"，工具自动补上该参数。

**账单流水**（做费率/滑点辅助归因）：

```bash
okx --profile <live|demo> account bills \
  --instType SWAP --begin <ts> --limit 500 \
  [--archive] --json
```

**账户快照**（补充当前 context）：

```bash
okx --profile <live|demo> account balance --json
okx --profile <live|demo> account config --json
```

### 第二步：数据健康校验

```
总记录数期望 = min(参数上限, 真实交易笔数)
实际拉到 = 接口返回记录数
覆盖率 = 实际 / 期望
```

- 覆盖率 < 红线（默认 80%）→ 报告**不出**，告知"数据不完整，建议放宽时间窗或启用 --archive"
- 覆盖率 ≥ 黄线（95%）→ 正常出报告
- 覆盖率 80%-95% → 出报告但顶部标注 "⚠️ 数据覆盖率 XX%，结论仅供参考"

### 第三步：多维分桶

分别按下列维度 reduce 出 PnL：

- **按币种**：`groupby(instId) → sum(realizedPnl), count, winRate, avgPnl`
- **按方向**：`groupby(direction: long/short) → 同上`
- **按时段**：根据 `cTime - oTime` 持仓时长分桶（<6h=日内 / 6-24h=隔夜 / >24h=超隔夜），单独识别横跨周末的持仓
- **按杠杆**：`groupby(floor(lever))`
- **按账户类型**：`groupby(instType: SWAP/FUTURES/SPOT)`

### 第四步：生成瀑布 & 洞察

- 对币种按 |贡献占比| 排序取 Top N，剩下折叠为"其他"
- 文字版瀑布：用 `█` 按占比 15 格满宽度渲染
- 洞察规则（全自动，基于阈值判定）：
  - 单品种贡献 > 50% → "集中度偏高"
  - 某方向胜率 < 45% → "反向操作效率低"
  - 某时段胜率 <  45% → "该时段应减少操作"
  - 最大亏损品种 > 总 PnL 的 20% → "黑洞品种"
- 每条洞察对应一条可执行改进建议（具体数字，不要空话）

### 第五步：输出中文 Markdown 报告

见下节 **输出模板**。

## 🛡️ 数据健康红黄线

本 Skill 只读不下单，所以"风控"对应的是**数据完整性**。

### 🔴 红线（自动停止出报告）

1. **采样覆盖率 < 80%**（默认阈值）
   → 告知："数据仅拉到 X 笔，覆盖率 Y%，无法生成可靠归因。建议：放宽时间窗 / 启用 --archive / 换 profile"
2. **API 连续失败 3 次**
   → 停止本次复盘，提示用户检查网络或 API 限流
3. **Profile 未确认**
   → 停下来问

### 🟡 黄线（出报告但标注警告）

1. 覆盖率 80%-95% → 顶部标 "⚠️ 数据覆盖率 XX%"
2. 时间窗 >7 天但未加 `--archive` → 自动补上并告知
3. 总交易笔数 < 10 → 标 "⚠️ 样本不足，结论仅供参考"

## 🚧 异常处理

| 场景 | 处理方式 |
|------|---------|
| API 调用失败 | 等 30s 重试，连续 3 次失败 → 告知用户、停止本次 |
| 无持仓历史（新账户） | 告知 "该时间窗无平仓记录"，建议换时间窗或 profile |
| positions-history 为空但 bills 有交易 | 提示可能是未平仓品种，建议扩大时间窗或查 `okx account positions` 看当前持仓 |
| Demo 数据稀疏 | 在报告顶部标 "⚠️ Demo 数据仅供格式演示" |
| 归档窗口越界（>90 天） | 分段拉取或告知用户该时段已无法检索 |
| 时间窗 <1 天 | 自动扩到 1 天 + 告知 "最小粒度为日" |
| 某些字段为 null | 按该维度不参与分桶，在报告尾部标注 "X 笔缺失方向信息" |

## ❓ 常见问题

**Q: 报告里的"已实现盈亏"是否包含手续费？**
A: 包含。`positions-history.realizedPnl` 是扣除手续费后的净值。如需单独看手续费占比，请用 `okx-review-fees-audit`。

**Q: 为什么 Top 5 加起来不等于总 PnL？**
A: 因为 Top 5 之外的品种合并到了"其他"，噪声阈值以下的品种被折叠。看明细请说"列出全部品种"。

**Q: 能不能按"主观标签"归因（比如这笔是突破、这笔是回踩）？**
A: 本 Skill 只基于客观数据。主观标签需配合交易日志，将在未来版本（v2.0）支持。

**Q: 现货交易能归因吗？**
A: 能。默认包含 SPOT，但 SPOT 的"方向"只有 long（买入），"时段"按买卖间隔计算。

**Q: 我有子账户，能合并复盘吗？**
A: 需要每个子账户单独跑 Skill 后手动拼接。跨子账户聚合将在 v2.0 支持。

**Q: 报告能否保存/导出？**
A: 可。说"把这份报告保存为 Markdown 文件"，工具会输出到本地。

**Q: 为什么做空胜率会显著低于做多？**
A: 加密市场长期偏多头，这是统计常态，不代表你策略有问题。真正需要警惕的是：做空**亏损额度**占总亏损 >50%，或做空胜率连续 3 次复盘 <35%。
