# 权益曲线回放 + 最大回撤体检 — 看清你是怎么跌下去、又怎么爬回来

**解决一句话问题**：这段时间我的资金曲线真实长什么样，最大回撤发生在什么时候，恢复花了多久？

只读复盘 Skill，不下任何单。基于 `account bills` 的 `balChg` 按时间累加重建权益路径，并用 `account balance` 作为当前锚点校正末值，输出峰谷区间、MDD、水下时长和恢复效率。

## 🔐 凭证与 Profile 校验（必跑，每次）

### Step A — 凭证检查

```bash
okx config show      # 验证配置（输出已脱敏）
```

- 无配置 / 报错 → **停止一切操作**，引导用户跑 `okx config init`
- 有配置 → 进 Step B

### Step B — Profile 确认（必填）

`--profile` 对所有鉴权命令强制必填。只有两个值：

| 值 | 模式 | 资金 |
|---|---|---|
| `live` | 实盘 | 真实资金 |
| `demo` | 模拟盘 | 模拟资金 |

**决策规则**：
1. 用户当前消息有明确意图（“实盘”/“live”/“真仓” → `live`；“模拟”/“demo”/“测试” → `demo`）→ 使用并告知：“使用 --profile live（实盘）”
2. 当前消息未声明 → 查上下文是否已有 profile：
   - 有 → 继续使用，告知：“沿用之前的 --profile live”
   - 无 → 问 “live（实盘）还是 demo（模拟盘）？”，**等回答再继续**

### 401 认证失败

若任何命令返回 401：
1. **立即停止**，不要重试
2. 告知用户：“鉴权失败（401），API Key 可能过期或无效”
3. 引导用户本地编辑 `~/.okx/config.toml` 更新 `api_key / secret_key / passphrase`（**不要让用户把密钥粘到对话里**）
4. 跑 `okx config show` 验证
5. 才可重试原命令

## 🔁 核心流程

### 第一步：拉取原始数据

**账单流水（权益重建主数据）**：

```bash
okx --profile <live|demo> account bills \
  --begin <开始时间戳ms> --end <结束时间戳ms> \
  --limit 500 \
  [--archive] --json
```

**账户余额（末端锚点）**：

```bash
okx --profile <live|demo> account balance --json
okx --profile <live|demo> account config --json
```

> 若“剔除入金出金=是”，会过滤非交易性 `bill type`，仅保留交易损益、手续费、资金费等交易相关项。

### 第二步：数据健康校验

```text
应有记录数 = min(参数上限, 时间窗内真实流水量)
实际记录数 = bills 返回条数
覆盖率 = 实际 / 应有
```

- 覆盖率 < 80%：拒绝出报告，提示“数据不完整，请缩短时间窗或启用 archive”
- 80%-95%：可出报告，但顶部标注“⚠️ 置信度中等”
- ≥95%：正常出报告

### 第三步：权益曲线重建

1. 将 `bills` 按 `ts` 升序排序
2. 以“起点资金”作为 `equity_0`
3. 逐条累加 `balChg` 得到 `equity_t`
4. 用 `account balance` 当前值做尾点一致性校正（误差阈值默认 0.5%）
5. 按采样粒度重采样到固定宽度

### 第四步：回撤识别与洞察

- 逐点维护 `running_peak`
- `drawdown_t = (equity_t - running_peak) / running_peak`
- 最大负值对应 MDD，回到峰值对应恢复点
- 洞察规则：
  - MDD > 20%：高风险告警
  - 水下 > 14 天：建议降低仓位与频率
  - Calmar < 1：标记“策略效率低”

### 第五步：输出中文 Markdown 报告

输出包含：曲线图、峰谷时间、分段回撤 Top3、风险诊断、行动建议。

## ⏸️ 暂停/恢复

- 暂停：`“暂停权益曲线复盘”`
- 恢复：`“恢复权益曲线复盘”`
- 临时跳过一次：`“这周先不生成”`
- 恢复后沿用最近一次参数；若未找到历史参数，则回退默认配置并二次确认。

---

## 🚧 异常处理

1. `bills` 空结果：提示“该时间窗无可用流水”，建议扩大时间窗。
2. 数据覆盖不足：给出缺口时间段，建议启用 `--archive` 或缩短窗口。
3. 尾点校正偏差过大：提示“存在多币种折算或跨账户转账影响”，自动降级为“相对曲线”模式。
4. 字段缺失（`balChg/ts`）：跳过异常记录并统计跳过比例。
5. 接口限流（429）：指数退避重试，超过上限则停止。

## ❓ Q&A

1. **Q：我只想看 BTC 相关权益变化，可以吗？**
   **A：可以。可在参数里指定 `instId` 过滤，只重建 BTC 相关流水曲线。**

2. **Q：Demo 账户能用吗？**
   **A：能。将 `--profile demo` 作为必填即可，输出逻辑一致。**

3. **Q：为什么我的 MDD 看起来比预期大？**
   **A：常见原因是包含了资金费和手续费，或未剔除入金出金。可切换口径重算。**

4. **Q：报告能保存到文件吗？**
   **A：可以，支持输出到 Markdown 文件，并可配合定时任务按日/周归档。**

5. **Q：能合并子账户一起看吗？**
   **A：默认按当前凭证账户。若你先在外部汇总子账户账单，再传入可做统一重建。**

6. **Q：采样用“交易级”还是“日级”更好？**
   **A：交易级更细但噪声大；日级更稳适合看风控。通常建议先日级，再局部放大。**

7. **Q：Calmar 低就一定要停策略吗？**
   **A：不一定。先看是否处于策略回撤期；若连续多期 <1，再考虑降仓或切换策略。**

8. **Q：如果只看到水下没恢复，该怎么解读？**
   **A：说明当前仍未回到峰值，重点关注回撤持续时间与仓位暴露，而不是短期反弹。**
