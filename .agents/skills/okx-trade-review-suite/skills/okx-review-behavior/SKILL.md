# 行为指纹复盘 — 追高、割肉、报复交易一次看清

**解决一句话问题**：我亏钱是因为行情，还是因为自己在错误时机做了错误动作？

只读复盘 Skill，不下任何单。基于 `positions-history` 与入/平仓时段 `market candles` 上下文，识别五类典型非理性行为，并给出行为纠偏清单。

## 🔐 凭证与 Profile 校验（必跑，每次）

### Step A — 凭证检查

```bash
okx config show      # 验证配置（输出已脱敏）
```

- 无配置 / 报错 → **停止一切操作**，引导用户跑 `okx config init`
- 有配置 → 进 Step B

### Step B — Profile 确认（必填）

`--profile` 对所有鉴权命令强制必填。只有两个值：

| 值 | 模式 | 资金 |
|---|---|---|
| `live` | 实盘 | 真实资金 |
| `demo` | 模拟盘 | 模拟资金 |

**决策规则**：
1. 用户当前消息有明确意图（“实盘”/“live”/“真仓” → `live`；“模拟”/“demo”/“测试” → `demo`）→ 使用并告知：“使用 --profile live（实盘）”
2. 当前消息未声明 → 查上下文是否已有 profile：
   - 有 → 继续使用，告知：“沿用之前的 --profile live”
   - 无 → 问 “live（实盘）还是 demo（模拟盘）？”，**等回答再继续**

### 401 认证失败

若任何命令返回 401：
1. **立即停止**，不要重试
2. 告知用户：“鉴权失败（401），API Key 可能过期或无效”
3. 引导用户本地编辑 `~/.okx/config.toml` 更新 `api_key / secret_key / passphrase`（**不要让用户把密钥粘到对话里**）
4. 跑 `okx config show` 验证
5. 才可重试原命令

## 🔁 核心流程

### 第一步：拉取原始数据

```bash
okx --profile <live|demo> account positions-history \
  --instType SWAP --begin <ts> --end <ts> \
  --limit 500 [--archive] --json

okx market candles --instId <instId> --bar 5m --limit 300 --json
okx market candles --instId <instId> --bar 1H --limit 240 --json
```

### 第二步：数据健康校验

- 校验成交记录完整性（`oTime/cTime/openAvgPx/closeAvgPx`）
- 校验 K 线时间覆盖入场与平仓前后窗口
- 覆盖率不足则降级为“仅基于成交价格行为”

### 第三步：行为识别

- **追高**：入场价距离 24h 高点 < 阈值（默认 2%）
- **割肉**：平仓前 1h 反弹 > 阈值（默认 1%）且平后继续反弹
- **报复交易**：亏损平仓后 N 分钟内再次开仓
- **FOMO 加仓**：已有盈利仓位，且在更高价继续加仓
- **死扛**：浮亏低于阈值（默认 -10%）且持有 >48h

### 第四步：热力评分与洞察

- 计算各行为发生率 = 行为次数 / 有效样本数
- 生成行为热力等级（低/中/高）
- 按影响金额和频次排序输出 Top 案例

洞察规则：
- 追高率 >30%：入场纪律告警
- 报复交易 ≥3 次：情绪交易告警
- 割肉率 >40%：平仓纪律告警

### 第五步：输出中文 Markdown 报告

输出行为热力表、Top 案例、纠偏动作与下期观测指标。

## ⏸️ 暂停/恢复

- 暂停：`“暂停行为指纹复盘”`
- 恢复：`“恢复行为指纹复盘”`
- 单次暂停：`“这周不做行为复盘”`

---

## 🚧 异常处理

1. K 线缺失：退化为“成交价上下文”判定并附低置信提示。
2. 成交时间缺失：剔除异常样本并标注比例。
3. 报复交易误判风险：同品种、同方向重复挂单会触发模糊判定，需标注。
4. 极端波动日：行为阈值自动放宽 20%，避免误伤。
5. API 限流：指数退避重试，失败后停止本次任务。

## ❓ Q&A

1. **Q：追高率高一定会亏钱吗？**
   **A：不一定，但长期会显著拉低盈亏比，尤其在震荡市更明显。**

2. **Q：割肉判定会不会把正常止损也算进去？**
   **A：会尽量区分。只有“平仓前已反弹且平后继续反弹”的模式才归入割肉。**

3. **Q：报复交易怎么避免误判？**
   **A：可调大时间窗并限制“同品种同方向+仓位放大”同时满足才算报复。**

4. **Q：FOMO 加仓是不是一定不对？**
   **A：不是。若有明确趋势策略和风控上限，FOMO 也可被规则化。**

5. **Q：支持 Demo 盘吗？**
   **A：支持，`--profile demo` 可用同样行为判定流程。**

6. **Q：案例里会暴露我的 API 信息吗？**
   **A：不会，报告仅展示交易字段，不输出任何密钥内容。**

7. **Q：我只想看追高和报复交易两项，能行吗？**
   **A：可以，支持按模块开关，仅输出指定行为。**

8. **Q：报告能用于团队交易纪律复盘吗？**
   **A：可以，建议配合固定阈值与统一动作清单，方便跨周期比较。**
