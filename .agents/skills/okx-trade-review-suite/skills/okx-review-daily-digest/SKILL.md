# 日/周/月复盘聚合报告 — 一条命令拿到全维度复盘结论

**解决一句话问题**：不用来回看多个模块，我能不能一次性拿到完整复盘和本周期最该做的 3 件事？

只读复盘 Skill，不下任何单。该 Skill 只负责路由与拼装，显式调用 7 个子 Skill 产出子报告，再生成统一总览与行动清单。

## ⚙️ 可配置参数

首次使用时逐项确认或说“用默认”跳过。

### 复盘参数

| 参数 | 默认值 | 可选范围 | 说明 |
|------|--------|----------|------|
| 周期 | 周 | 日 / 周 / 月 | 聚合粒度 |
| 包含模块 | 全部 7 个 | 可勾选子模块 | 支持只聚合部分模块 |
| 详细度 | 标准 | 简要 / 标准 / 完整 | 决定子报告展开层级 |
| 输出方式 | 控制台 | 控制台 / Markdown 文件 / 预留 IM 钩子 | 投递目标 |
| 报告路径 | `./reports` | 任意可写目录 | 文件输出路径 |
| 综合建议条数 | 3 | 1-10 | 输出行动项数量 |
| 优先级策略 | 风控>行为>策略 | 固定或自定义 | 建议排序逻辑 |
| 定时触发 | 关闭 | Cron/固定时点 | 周期化运行 |

### 数据健康参数

| 参数 | 默认值 | 可选范围 | 说明 |
|------|--------|----------|------|
| 子模块最低覆盖率 | 80% | 50%-95% | 任一子模块低于阈值则降级 |
| 聚合最小模块数 | 5 | 3-7 | 低于阈值不出总评 |
| 子模块超时 | 90 秒 | 30-300 秒 | 单模块执行超时阈值 |
| 重试次数 | 2 | 0-5 | 子模块失败重试 |
| 降级策略 | 跳过失败模块 | 跳过/中止 | 聚合容错模式 |

**所有参数随时可在对话中修改**，例如：
- “改成月报，只要完整度”
- “这次只要权益曲线 + fees + behavior”
- “输出到 markdown 文件”
- “综合建议给我 5 条”

## 🔐 凭证与 Profile 校验（必跑，每次）

### Step A — 凭证检查

```bash
okx config show      # 验证配置（输出已脱敏）
```

- 无配置 / 报错 → **停止一切操作**，引导用户跑 `okx config init`
- 有配置 → 进 Step B

### Step B — Profile 确认（必填）

`--profile` 对所有鉴权命令强制必填。只有两个值：

| 值 | 模式 | 资金 |
|---|---|---|
| `live` | 实盘 | 真实资金 |
| `demo` | 模拟盘 | 模拟资金 |

**决策规则**：
1. 用户当前消息有明确意图（“实盘”/“live”/“真仓” → `live`；“模拟”/“demo”/“测试” → `demo`）→ 使用并告知：“使用 --profile live（实盘）”
2. 当前消息未声明 → 查上下文是否已有 profile：
   - 有 → 继续使用，告知：“沿用之前的 --profile live”
   - 无 → 问 “live（实盘）还是 demo（模拟盘）？”，**等回答再继续**

### 401 认证失败

若任何命令返回 401：
1. **立即停止**，不要重试
2. 告知用户：“鉴权失败（401），API Key 可能过期或无效”
3. 引导用户本地编辑 `~/.okx/config.toml` 更新 `api_key / secret_key / passphrase`（**不要让用户把密钥粘到对话里**）
4. 跑 `okx config show` 验证
5. 才可重试原命令

## 🔁 核心流程

### 第一步：拉取聚合上下文

```bash
okx --profile <live|demo> account config --json
okx --profile <live|demo> account balance --json
```

用于统一报告头部上下文，不在本 Skill 重复做交易级分析。

### 第二步：显式调用 7 个子 Skill（按顺序）

```text
1) okx-review-attribution
2) okx-review-equity-curve
3) okx-review-streak
4) okx-review-benchmark
5) okx-review-behavior
6) okx-review-fees-audit
7) okx-review-hold-duration
```

说明：
- 本 Skill 只调用子 Skill 并收集结果，不重复实现它们的分析逻辑。
- 若用户在“包含模块”里取消某模块，则跳过对应调用。

### 第三步：子报告健康校验

- 统计成功模块数、覆盖率、是否超时
- 达不到“聚合最小模块数”时，不输出总建议，只输出已成功模块清单

### 第四步：拼装总报告与综合建议

- 按固定章节顺序拼装：
  - 顶部总览卡
  - 归因段
  - 权益曲线段
  - streak 段
  - benchmark 段
  - behavior 段
  - fees 段
  - hold-duration 段
  - 综合建议段
- 对所有子模块建议去重并按优先级排序：`风控 > 行为 > 策略`
- 生成“本周最重要的 3 件事”

### 第五步：输出与投递

- 输出到控制台或 Markdown 文件
- 若配置了 IM 钩子（预留），则构造消息体等待外部发送

## 🚧 异常处理

1. 某子模块失败：按降级策略跳过并在总报中列出失败原因。
2. 子模块结果口径冲突：以风控模块优先并附“口径说明”。
3. 输出写文件失败：回退控制台输出并提示路径权限。
4. 定时触发超时：记录超时模块并在下次优先重试。
5. 全模块失败：只输出诊断信息，不生成错误结论。

## ❓ Q&A

1. **Q：我只想要“周报简版”，可以吗？**
   **A：可以，把详细度改成“简要”，并只保留你关心的模块。**

2. **Q：能不能每天自动出一份并落地到文件？**
   **A：支持，设置日报周期和 Markdown 输出路径即可。**

3. **Q：如果某个子模块报错，总报会失败吗？**
   **A：默认不会，系统会降级跳过并在报告中标明缺失模块。**

4. **Q：综合建议怎么排序？**
   **A：默认按“风控 > 行为 > 策略”优先级，并去重后输出 Top3。**

5. **Q：可以把结果推到 IM 吗？**
   **A：支持预留钩子，目前会先生成可发送消息体，交给外部通道投递。**

6. **Q：Demo 盘和实盘都能出总报吗？**
   **A：可以，`--profile live/demo` 均可；建议分开订阅避免混淆。**

7. **Q：我可以把 attribution 从总报里移除吗？**
   **A：可以，在“包含模块”里取消勾选即可。**

8. **Q：总报里的结论会不会互相打架？**
   **A：会做建议去重和优先级裁决，冲突建议会标注来源模块。**
