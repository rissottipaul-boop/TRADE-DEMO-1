# Alpha 计量仪 — 主动交易到底有没有跑赢“躺平基准”

**解决一句话问题**：同一时间窗下，我的主动交易相对被动策略到底多赚了多少（或少亏了多少）？

只读复盘 Skill，不下任何单。基于实际交易收益与市场 K 线构建多组基准组合，给出风险调整后对比与可执行切换建议。

## ⚙️ 可配置参数

首次使用时逐项确认或说“用默认”跳过。

### 复盘参数

| 参数 | 默认值 | 可选范围 | 说明 |
|------|--------|----------|------|
| 时间窗 | 最近 90 天 | 30d / 90d / 180d / 自定义 | 同窗对比区间 |
| 基准种类 | BH-BTC + DCA-BTC + SMA20 | 可多选：BH-BTC/BH-ETH/SMA20/SMA60/DCA-BTC | 同时输出多组对比 |
| 基准品种 | BTC | BTC / ETH | SMA 与 DCA 的基础品种 |
| 年化折算 | 365 | 365 / 252 | 年化收益口径 |
| 无风险利率 | 3% | 0%-8% | Sharpe/Sortino 口径 |
| 滚动比较窗 | 14 天 | 7-60 天 | 胜过基准概率统计窗口 |
| DCA 频率 | 每日 | 每日/每周 | DCA 模拟规则 |
| 手续费口径 | 含实际费用 | 含/不含 | 主动收益是否含费 |

### 数据健康参数

| 参数 | 默认值 | 可选范围 | 说明 |
|------|--------|----------|------|
| 覆盖率红线 | 80% | 50%-95% | 低于红线拒绝结论 |
| 覆盖率黄线 | 95% | 80%-99% | 黄线标注置信区间 |
| K 线缺口容忍 | 2% | 0%-10% | 缺口过大则降级分析 |
| 归档自动切换 | 开启 | 开启/关闭 | 历史成交自动 archive |
| API 重试次数 | 3 | 1-5 | 拉数失败重试 |

**所有参数随时可在对话中修改**，例如：
- “只比 BH-BTC 和 DCA”
- “年化口径换 252”
- “无风险利率改 2%”
- “滚动比较窗改 30 天”

## 🔐 凭证与 Profile 校验（必跑，每次）

### Step A — 凭证检查

```bash
okx config show      # 验证配置（输出已脱敏）
```

- 无配置 / 报错 → **停止一切操作**，引导用户跑 `okx config init`
- 有配置 → 进 Step B

### Step B — Profile 确认（必填）

`--profile` 对所有鉴权命令强制必填。只有两个值：

| 值 | 模式 | 资金 |
|---|---|---|
| `live` | 实盘 | 真实资金 |
| `demo` | 模拟盘 | 模拟资金 |

**决策规则**：
1. 用户当前消息有明确意图（“实盘”/“live”/“真仓” → `live`；“模拟”/“demo”/“测试” → `demo`）→ 使用并告知：“使用 --profile live（实盘）”
2. 当前消息未声明 → 查上下文是否已有 profile：
   - 有 → 继续使用，告知：“沿用之前的 --profile live”
   - 无 → 问 “live（实盘）还是 demo（模拟盘）？”，**等回答再继续**

### 401 认证失败

若任何命令返回 401：
1. **立即停止**，不要重试
2. 告知用户：“鉴权失败（401），API Key 可能过期或无效”
3. 引导用户本地编辑 `~/.okx/config.toml` 更新 `api_key / secret_key / passphrase`（**不要让用户把密钥粘到对话里**）
4. 跑 `okx config show` 验证
5. 才可重试原命令

## 🔁 核心流程

### 第一步：拉取原始数据

```bash
okx --profile <live|demo> account positions-history \
  --instType SWAP --begin <ts> --end <ts> --limit 500 [--archive] --json

okx --profile <live|demo> account bills \
  --begin <ts> --end <ts> --limit 500 [--archive] --json

okx market candles --instId <BTC-USDT-SWAP> --bar 1D --limit 300 --json
okx market candles --instId <ETH-USDT-SWAP> --bar 1D --limit 300 --json
```

### 第二步：数据健康校验

- 成交覆盖率、账单覆盖率、K 线连续性三重校验
- 缺口 > 红线时拒绝 alpha 结论，降级为“描述性收益比较”

### 第三步：构建基准收益序列

- `BH`：窗口起点一次买入并持有到终点
- `SMA(20/60)`：收盘价上穿持有、下穿空仓（不做杠杆）
- `DCA`：按频率定额买入 BTC
- 实际组合：由 `positions-history + bills` 汇总净收益

### 第四步：风险调整与超额收益计算

- 计算各序列日收益
- 输出 Sharpe / Sortino
- 以选定主基准计算 Alpha、Beta、Information Ratio
- 统计滚动窗口中“主动收益 > 基准收益”的概率

洞察规则：
- `alpha < 0` 且 `Sharpe < 0.5`：建议转被动定投
- `Beta > 1.5`：仓位暴露过高
- `Information Ratio > 0.5`：有效 alpha

### 第五步：输出中文 Markdown 报告

输出多列对比表、10 格 ASCII 柱、负 alpha 劝退话术、行动建议。

## ⏸️ 暂停/恢复

- 暂停：`“暂停 benchmark 复盘”`
- 恢复：`“恢复 benchmark 复盘”`
- 改周期：`“改成每月 1 号生成”`
- 恢复时沿用最近一次基准集合配置。

---

## 🚧 异常处理

1. K 线缺口过大：降级为 BH-only 对比并提示缺口。
2. 成交样本不足：延长窗口或改为周级比较。
3. `bills` 与 `positions-history` 净值不一致：以净值口径优先并标注误差。
4. 基准品种无数据：切换到可用品种并告知。
5. 429/5xx：重试失败后终止并返回重跑建议。

## ❓ Q&A

1. **Q：我可以只比 ETH 基准吗？**
   **A：可以，基准品种可切换为 ETH，也可同时保留 BTC/ETH 双基准。**

2. **Q：SMA 基准为什么有时看起来太“理想化”？**
   **A：默认不计滑点和冲击成本，建议结合 fees-audit 一起看真实可执行性。**

3. **Q：alpha 为负是不是马上停策略？**
   **A：建议先看是否连续两期为负，并结合 Beta 与 IR 再决定是否切换仓位结构。**

4. **Q：为什么我收益更高但 Sharpe 更差？**
   **A：说明波动更大，单位风险换来的收益并不优，需看风险调整收益。**

5. **Q：DCA 频率改成每周会影响对比吗？**
   **A：会，定投节奏是关键变量，建议固定频率后做跨期可比。**

6. **Q：支持 Demo 盘吗？**
   **A：支持，`--profile demo` 可完整运行同样流程。**

7. **Q：报告能导出给团队周会吗？**
   **A：支持 Markdown 输出，适合直接贴到周报文档。**

8. **Q：Information Ratio 多高才算有意义？**
   **A：经验上 >0.5 才算“有效 alpha”，<0 通常表示无持续超额能力。**
