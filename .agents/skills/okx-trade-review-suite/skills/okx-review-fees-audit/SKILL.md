# 手续费与滑点体检 — 先把“看不见的漏损”堵上

**解决一句话问题**：我到底是策略不行，还是利润被手续费和执行成本吃掉了？

只读复盘 Skill，不下任何单。基于 `bills(type=8)`、`account fees` 与 `positions-history` 计算成本结构，输出费用瀑布、maker/taker 结构与可节省空间。

## 🔐 凭证与 Profile 校验（必跑，每次）

### Step A — 凭证检查

```bash
okx config show      # 验证配置（输出已脱敏）
```

- 无配置 / 报错 → **停止一切操作**，引导用户跑 `okx config init`
- 有配置 → 进 Step B

### Step B — Profile 确认（必填）

`--profile` 对所有鉴权命令强制必填。只有两个值：

| 值 | 模式 | 资金 |
|---|---|---|
| `live` | 实盘 | 真实资金 |
| `demo` | 模拟盘 | 模拟资金 |

**决策规则**：
1. 用户当前消息有明确意图（“实盘”/“live”/“真仓” → `live`；“模拟”/“demo”/“测试” → `demo`）→ 使用并告知：“使用 --profile live（实盘）”
2. 当前消息未声明 → 查上下文是否已有 profile：
   - 有 → 继续使用，告知：“沿用之前的 --profile live”
   - 无 → 问 “live（实盘）还是 demo（模拟盘）？”，**等回答再继续**

### 401 认证失败

若任何命令返回 401：
1. **立即停止**，不要重试
2. 告知用户：“鉴权失败（401），API Key 可能过期或无效”
3. 引导用户本地编辑 `~/.okx/config.toml` 更新 `api_key / secret_key / passphrase`（**不要让用户把密钥粘到对话里**）
4. 跑 `okx config show` 验证
5. 才可重试原命令

## 🔁 核心流程

### 第一步：拉取原始数据

```bash
okx --profile <live|demo> account bills \
  --type 8 --begin <ts> --end <ts> \
  --limit 500 [--archive] --json

okx --profile <live|demo> account fees --json

okx --profile <live|demo> account positions-history \
  --begin <ts> --end <ts> --limit 500 [--archive] --json
```

若“包含资金费率=是”，额外读取 `bills type=4` 并合并。

### 第二步：数据健康校验

- 手续费流水与成交笔数对齐检查
- 费率档位与实际收费口径一致性校验
- 覆盖不足或对齐失败时降级输出“估算版”

### 第三步：费用结构分析

1. 汇总总手续费与平均每笔费用
2. 计算 `手续费/毛利润` 比例
3. 统计 maker/taker 笔数比与费率使用比
4. 分品种统计费用占比，提取 Top N

### 第四步：节省空间估算与洞察

- 估算“若全 maker”节省金额
- 与 maker 目标比例比较，给出提升路径
- 洞察规则：
  - 费用占比 >5%：过度交易告警
  - maker 比例 <50%：建议增加限价成交
  - 单品种费用占比 >20%：建议减频或改执行策略

### 第五步：输出中文 Markdown 报告

输出瀑布图、ASCII 饼图、高费率品种排行、优化动作清单。

## 🚧 异常处理

1. 无 `type=8` 流水：提示“窗口内无手续费记录或权限不足”。
2. 费率档位获取失败：降级为历史平均费率估算。
3. 毛利润接近 0：费用占比容易畸高，自动附稳定性提示。
4. 多币种费用难以直接汇总：按折算币统一口径后再统计。
5. 429/5xx：重试失败后终止并返回补跑建议。

## ❓ Q&A

1. **Q：手续费占比多少算健康？**
   **A：经验上 <3% 较健康，3%-5% 需关注，>5% 通常说明交易频率或执行方式有问题。**

2. **Q：maker 比例低就一定不好吗？**
   **A：不绝对，但长期低 maker 往往意味着成本劣势，除非策略依赖极快成交。**

3. **Q：支持把资金费率单独拆出来吗？**
   **A：支持，可开关“包含资金费率”，并在报告中单列展示。**

4. **Q：全 maker 节省估算会不会太理想化？**
   **A：是上限估算，实际要扣除挂单未成交与机会成本。**

5. **Q：Demo 盘能做费用体检吗？**
   **A：可以，逻辑一致，但模拟成交环境可能与实盘成本结构不同。**

6. **Q：高费率品种一定要停吗？**
   **A：不一定，先看该品种净贡献；若费用占比高且净贡献低，再考虑降频。**

7. **Q：报告可以按品种导出吗？**
   **A：可以，支持输出完整分品种费率表到 Markdown。**

8. **Q：我做现货和合约混合，能一起算吗？**
   **A：可以，但建议先分开看，再看合并口径，避免结论被互相稀释。**
