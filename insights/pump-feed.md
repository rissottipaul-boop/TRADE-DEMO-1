# Лента данных для памп-сигналов: demo или live (PUMP-FEED)

- **Дата:** 2026-09-24, замеры 20:24–20:40+05
- **Статус:** validated. Эмпирика: публичные GET с заголовком `x-simulated-trading: 1` и без него, ордеров нет. Плюс исходник okx CLI 1.4.8 и CHANGELOG `okx/agent-trade-kit`.
- **Задача:** PUMP-FEED (из PUMP-CODIFY)
- **Решение:**
  - сигналы памп-сканера (универсум, импульс, объём, RSI/MA/MACD) берём из **live**-ленты;
  - demo-лента нужна только там, где исполняется demo-ордер: стакан и сверка цены перед входом;
  - история для PUMP-BT — только live.

## 1. Ответ: влияет ли `x-simulated-trading` на публичные рыночные данные

**Да, влияет.** С заголовком OKX отдаёт данные отдельного симулированного рынка: свой список инструментов, свои сделки, свой стакан и свои свечи. Цена ликвидных пар привязана к live, но объём, сделки и глубина у demo свои.

| Эндпоинт (24.09, 20:28+05) | live (без заголовка) | demo (с заголовком) |
| --- | --- | --- |
| `public/instruments?instType=SPOT` | 1415 | 571 |
| `market/tickers?instType=SPOT` / `SWAP` | 1415 / 492 | 563 / 184 |
| `market/ticker` BTC-USDT `vol24h` | 8 871 BTC | 89 999 BTC (×10) |
| `market/ticker` BTC-USDT `last` | 84 084.6 | 84 103.3 |

| `history-candles` ETH-USDT 1D, 2025-10-01 | high 4345, объём 172 315 ETH | high 4400, объём 47.3 млн ETH (×275) |

Источники (независимые):

1. **Эмпирика проекта** — таблица выше и §2–3 (скрипт в scratchpad, только публичные GET, пауза 0.25 с).
2. **`okx/agent-trade-kit` CHANGELOG, 1.3.0 / 1.3.0-beta.5 (2026-04-08)**, официальный репозиторий OKX. Флаг `--demo` / `demo: true` «targets OKX's simulated trading market data environment (`x-simulated-trading: 1`)». Там же: раньше сервер в demo-режиме «caused all market data requests to return simulated trading data», поэтому market-инструменты по умолчанию переведены на live.
3. **Исходник okx CLI 1.4.8** (`@okx_ai/okx-trade-cli/dist/index.js`):
   - `publicGet(path, query, rateLimit, simulatedTrading)`;
   - market-команды передают `demo: v.demo ?? false`;
   - заголовок ставится, только если `simulatedTrading` истинно.

   Проверка: `okx --demo market ticker BTC-USDT` → `vol24h` 89 987, `okx market ticker BTC-USDT` → 8 867. Значит, **сканы №1–6 Pump Risk Taker (`okx --demo market …` и сканер с `--feed demo`) шли по demo-ленте.**
4. Косвенный источник — официальная документация OKX (`okx/ai-builder-openapi-md`, `introduction.md`, «Demo Trading Services»): у demo свой публичный WebSocket `wss://wspap.okx.com:8443/ws/v5/public`, отдельный от `ws.okx.com`.

**Как разрешено противоречие:**

| Утверждение | Где | Вердикт |
| --- | --- | --- |
| Demo-свечи строятся из demo-сделок: плоские бары без сделок, выбросы объёма ×1000 | докстринг `src/pump_scanner.py`, `okx-api.md` §10 п. 8 | **Верно по сути.** Плоский бар всегда с нулевым объёмом (§2), у demo своя последовательность `tradeId`. Внутренний механизм OKX не документирован: «из сделок demo» — вывод из наблюдений |
| «Рыночные данные demo = live-книга» | докстринг `OkxPublicClient`, `src/backtest/data.py:360` | **Неверно как общее утверждение.** `demo-slippage.md` §5 говорит только о цене исполнения market-ордера BTC-USDT. Там же §7.3.2: «демо-стакан имеет собственную динамику глубины, не копию live». Сам код `data.py` верен: заголовок не шлёт, бэктест идёт по live |
| «Market data … same regardless of demo/live», «`--demo` does not affect market data via CLI» | `.agents/skills/okx-cex-market/SKILL.md` стр. 46 и 153 | **Неверно для CLI 1.4.8** (источники 2–3) |

| Demo-клиент по умолчанию получает симулированный стакан | `okx-api.md` §2 | **Верно** |

## 4. Рекомендация

1. **Сканер — лента `live` по умолчанию** для всех сигналов: универсум по live `volCcy24h`, импульс, vol×, RSI, MA20, MACD.
   - На demo-ленте фильтр объёма работает на шуме: 48% пропусков и ложные кандидаты.
   - Универсум demo на половину состоит из других пар.
   - `--feed demo` оставить для диагностики.
2. **Гибрид, который предложил Pump Risk Taker, — принят с условиями.** Пока карман торгует на demo, ордер исполняется в demo-книге, поэтому нужны проверки на стороне demo:
   - **универсум:** live топ-N ∩ demo `public/instruments` (`state=live`). Иначе сигнал по паре, которой нет в demo: 8 из 45 сейчас;
   - **проверка demo-цены перед входом:** demo-стакан двусторонний и |mid demo − mid live| / mid live ≤ 0.5% (порог = `--spread-max`). Мёртвые demo-пары отстают на 1.5–74% (ZEC 74%, XMSTR 39%, ARB 9.5%, XPL 1.5%); вход туда даст фиктивный PnL;
   - **ликвидность (PUMP-LIQ):**
     - глубина и спред — по обеим книгам, пара проходит, только если прошла обе: live — рынок, на котором будет работать правило; demo — где фактически исполнится ордер;
     - оборот (`turnover`) — только по live-свече, demo-оборот артефактный.
3. **PUMP-BT — только live-история.** `src/backtest/data.py` уже так делает, неверен только его докстринг.
4. **Прошлые данные — пометить.**
   - Строки `scan` в `data/pump_journal.jsonl` до переключения (поле `feed: demo`) и сканы №1–6 в `pump-scan-2026-09-24.md` — сигналы demo-ленты. Для оценки правил их не использовать.
   - Проверка повтора скана №5 (остаток PUMP-CODIFY) сверяется с demo-числами, поэтому после переключения её надо запускать с явным `--feed demo`.

Применимость: ценность высокая (без этого статистика памп-кармана и вердикт PUMP-BT считаются на артефактах), сложность низкая или средняя, риск низкий: только чтение публичных данных. Демо-исполнение не меняется.

## 6. Открытые вопросы

1. **Механизм demo-цены.** Цена ликвидных demo-пар держится у live (медиана 0.05%), а стакан состоит из однотипных уровней по 0.002069 ETH. Похоже на маркет-мейкеров OKX с привязкой к live, но это **не проверено**, документации нет. На решение не влияет.
2. **Demo-стратегии движка.** В demo движок читает публичный WS `wspap.okx.com` (`src/ws_client.py:417`), а CCXT sandbox шлёт заголовок и в REST. Значит, их сигналы (DCA, mean-reversion demo-прогон) считаются по demo-ленте.
   - На мажорах расхождение мало: close ETH — медиана 0.002% за 24 ч; BTC — 0.022% по одному снимку тикера, за 24 ч не мерили.
   - На альтах и в объёмных условиях — риск тот же, что у сканера.
   - Нужен аудит: задача FEED-ENGINE-AUDIT.
3. **Порог 0.5% для проверки demo-цены** выбран по данным одних суток (медиана у живых пар ≤ 0.48%, у мёртвых ≥ 1.5%). Подстроить по журналу первой недели.
