# Roadmap: план исполнения проекта полной автоматизации торговли (OKX)

- **Дата:** 2026-09-23
- **Статус:** idea (план; корректируется по мере валидации)
- **Основание:** [okx-api.md](okx-api.md) (validated), [spot-strategies.md](spot-strategies.md) (idea/validated), заметки пользователя (тренды 2026)

> Это инженерный план, а не финансовый совет. Каждая фаза завершается критерием выхода; без выполнения критерия к следующей не переходим.

**Параллельный трек — малый live (решение человека 2026-09-24).** Live-торговля начинается до выхода Фазы 1: отдельный суб-аккаунт с бюджетом $500–1 000 (план на 3 месяца — до $10 000), окно `ops/live-policy.json` ≤ 7 дней с продлением после еженедельного разбора, сначала только DCA-рукав через риск-ядро. Фазовая дисциплина снимается только для задач этого трека. Рукава, правило масштабирования, copy trading и блокеры в коде — [business-plan.md](business-plan.md).

Live-ключ потом — обязательно с IP-whitelist (иначе протухает за 14 дней неактивности). ⚠️ 24.09: `GET /account/config` у demo-ключа возвращает `perm = read_only,withdraw,trade` — «без withdraw» не выполнено (на demo-деньгах не опасно). Для live права ключа проверяет `src/live_preflight.py`: ключ с withdraw live не запустит ([okx-api.md](okx-api.md) §10 п. 12).
2. ✅ Инициализировать проект: Python + **CCXT** (`set_sandbox_mode(True)`), `.env` для ключей (в `.gitignore`), логирование, конфиг (регион-домен, account mode, position mode — зафиксировать до старта и не менять при открытых позициях).
3. ✅ Smoke-тест коннектора: подпись запроса, `GET /public/time` (синхронизация часов), баланс, place/cancel лимитного ордера в демо, чтение `sCode`/`sMsg` внутри `data[]`.
4. ✅ NTP-синхронизация времени на машине бота (дрейф +157 мс, норма).

**Критерий выхода:** ✅ ордер ставится/отменяется в демо, ошибки 50105/51020 распознаны и залогированы.

**Безопасность:** секреты и passphrase не хранятся в документации и не выводятся в отчёты; используйте только `.env`.

## Фаза 1. Данные и исполнение — 🔄 В РАБОТЕ (2026-09-24)

**Цель:** надёжный «водопровод»: рыночные данные + ордера + состояние.

1. ✅ WS public (tickers/books/candles) с heartbeat <30с, обработкой `notice 64008`, reconnect + ресинк.
2. ✅ Локальный стакан: snapshot → дельты по цепочке **seqId/prevSeqId** (разрыв → ресинк); checksum — по исходным строкам, если биржа его пришлёт.
3. ✅ WS private (login + канал `orders`) + периодическая REST-реконсиляция с метрикой рассинхрона — проверено на демо 2026-09-24.
4. ✅ Хранилище состояния (SQLite): ордера, позиции, сделки, equity-кривая.
5. ✅ `expTime` на ордерные запросы — **в HTTP-заголовке** (проверено: просроченный отвергается `sCode 50036`); throttler под лимиты (CCXT встроенный).
6. ✅ **Проверено:** tradingBot-эндпоинты (`grid/order-algo`, `ai-param`, `min-investment`) работают в Demo Trading.

**Критерий выхода:** 72 часа непрерывной работы на демо без рассинхрона состояния (WS vs REST совпадают). Осталось: нагрузочный тест + 72ч наблюдение.

**Найдено при выполнении:** OKX шлёт `checksum=0` в канале books и на demo, и на live (проверено 2026-09-24) — целостность стакана держится на цепочке seqId/prevSeqId. До исправления `expTime` уходил в тело запроса и биржей игнорировался. Детали — [phase1-progress.md](phase1-progress.md).

## Фаза 2. Первая стратегия и бэктестер (3–4 недели)

**Цель:** от бэктеста до демо-торговли одной стратегии.

1. **Бэктестер раньше стратегии:** anti-lookahead правила (сигнал на закрытии свечи, вход на открытии следующей; без `shift(-1)`/глобальных агрегатов), комиссии + проскальзывание, прогрев индикаторов, **walk-forward**. Дизайн утверждён: [backtester-design.md](backtester-design.md) (готово к реализации, 2026-09-24) — реализация в задаче BT-IMPL.
2. Стратегия №1 — **DCA на споте** (простейшая машина состояний; цель — обкатка пайплайна, не прибыль). **Внедрено (p1-dca-demo, 2026-09-24):** `src/dca_bot.py` (машина IDLE→BUYING→COOLDOWN, персистентность в `dca_state`), self-test зелёный (18 проверок), демо-прогон — 2 рыночные покупки BTC-USDT по ~$5, состояние восстанавливается после перезапуска.
3. Стратегия №2 — **Grid**: биржевой бот OKX (если доступен в демо) для эталона + своя реализация с правилом остановки всей сетки при выходе из диапазона.
4. Стратегия №3 — **mean-reversion (RSI/BB)** со стоп-лоссом и minimal ROI — первая сигнальная.
5. Метрики: не только PnL — max drawdown, Sharpe, win rate, avg trade, чувствительность к комиссиям/проскальзыванию. Помнить: статистическая точность ≠ прибыльность (микроструктура).

**Критерий выхода:** стратегия показывает устойчивый результат на walk-forward + ≥7–14 дней paper/dry-run без аномалий.

## Фаза 3. Риск-менеджмент и демо-бой (3–4 недели)

**Цель:** неубиваемость перед реальными деньгами.

1. Риск-модуль: сайзинг позиции (фикс-% капитала), дневной лимит убытка, max drawdown → circuit breaker (остановка всех стратегий), блокировка пары после серии убытков.
2. Kill-switch: ручная остановка + авто-отмена всех ордеров.
3. Мониторинг/алерты (Telegram-бот): сделки, ошибки API, разрывы WS, срабатывание circuit breaker.
4. Политика автономного live: отдельный live-профиль, ключ без withdraw и с IP-whitelist, выделенный бюджет, stop-loss, position sizing, дневной circuit breaker и kill-switch. После однократной настройки политика не требует подтверждения каждой сделки.

**Критерий выхода:** месяц на демо без единого инцидента потери состояния; риск-лимиты срабатывают в тестах.

## Фаза 4. Live на споте (минимальный капитал)

1. Live-ключ: read+trade, IP-whitelist, без withdraw. Регулярный приватный REST-вызов (иначе ключ протухнет через 14 дней «неактивности» — WS не считается!).
2. Одна стратегия, 1–2 ликвидные пары (BTC-USDT, ETH-USDT), минимальный сайзинг.
3. Еженедельный разбор: слиппедж vs бэктест, доля отказов, отклонение equity.

## Фаза 5+. Расширение (после стабильного live)

- **SWAP (perpetual):** шорт + плечо, funding-aware логика; учесть: MARK-свечи OKX ~3 мес. истории, posSide в hedge-режиме, reduceOnly, ликвидации.
- **COMBO (grid+DCA на фьючах)** — референс Bitsgap.
- **ML-слой:** информационные бары (Volume/Dollar/CUSUM) + Triple Barrier разметка; ML-фильтр входов поверх сигнальных стратегий; DRL — только как эксперимент с жёсткими рамками.
- **LLM-сентимент** как дополнительный фильтр (низкая надёжность заявленных результатов — проверять на собственных данных).
- Мультипарность/мультистратегия, при необходимости — суб-аккаунты OKX для rate limit.

## Принципы всего проекта (из инсайтов)

1. Demo используется для проверки; автономный live запускается только явно настроенным профилем и заранее заданной политикой риска, без ручного подтверждения каждой сделки.
2. Ключ без withdraw + IP-whitelist — всегда.
3. Статистическая красота бэктеста ≠ деньги: комиссии, проскальзывание, микроструктура.
4. Состояние — источник правды; биржа опрашивается для сверки, а не наоборот.
5. Каждая идея проходит через `insights/` → статус idea → validated → реализация.
