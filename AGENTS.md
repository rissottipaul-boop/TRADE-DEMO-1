# Регламент агентов проекта OKX-бота

Общие правила для всех агентов (Copilot-агенты из `.github/agents/`, Claude Code, любые субагенты). Файл агента описывает роль, этот — как работать вместе. Язык ответов и документов — русский.

Проект: полная автоматизация торговли на OKX, сначала demo. План и фазы — [insights/roadmap.md](insights/roadmap.md), текущая работа — [ops/board.md](ops/board.md).

## 1. Команда

| Агент | Роль | Пишет в |
| --- | --- | --- |
| **Project Orchestrator** | Автопилот: ведёт доску, делегирует задачи субагентам, принимает результат | `ops/board.md` |
| **Crypto Insight Hunter** | Исследования: идеи, API, стратегии, проверка фактов | `insights/` |
| **Insight Executor** | Код, тесты, скрипты по задачам с доски | `src/`, `tests/`, `ops/*.ps1`, документация |
| **OKX Trader** | Операции на бирже через `okx` CLI: ордера, grid/DCA-боты, баланс | `insights/` (журналы и отчёты) |
| **Pump Risk Taker** | Рисковый карман: импульсные сделки в пределах `pump-pocket.json` | `insights/pump-*.md`, `data/pump_journal.jsonl` |
| **Ops Sentinel** | Мониторинг движка, риска и ботов; аварийные действия в сторону безопасности | `ops/incidents.md`, `ops/board.md` |

Роли описаны в `.github/agents/*.agent.md`. Для Claude Code те же роли подключены субагентами `.claude/agents/*.md` (`insight-executor`, `crypto-insight-hunter`, `okx-trader`, `ops-sentinel`, `pump-risk-taker`). Это обёртки: субагент читает файл своей роли, поэтому источник правды один. Оркестратор в Claude Code — основная сессия.

## 2. Автономия: кто что решает

Правило асимметрии: **в сторону безопасности агент действует сам и сразу, в сторону риска — никогда.**

| Решает агент сам, без вопросов | Решает только человек (задача `needs-user`) |
| --- | --- |
| Выбор и порядок задач, декомпозиция, новые задачи на доске | Включение live-торговли (`ops/live-policy.json`) |
| Архитектура, рефакторинг, удаление дублей в коде | Сброс kill-switch и breaker'ов (`python -m src.ops reset …`) |
| Запуск и остановка движка, тестов, demo-экспериментов | Ослабление любого лимита риска (`src/risk.py`, `pump-pocket.json`) |
| Demo-ордера и demo-боты в пределах риск-лимитов | Секреты: `.env`, ключи, токены, профили `okx` CLI |
| Kill-switch, отмена ордеров, остановка ботов при инциденте | Удаление данных и баз состояния |
| Ужесточение лимитов, добавление проверок | Правка guard/автопилота (`ops/hooks/`, `.github/hooks/`, `ops/autopilot.json`) |
| Исследования, документация, статусы инсайтов | Вывод средств — **никогда и никем из агентов** |

Правую колонку механически обеспечивает хук `ops/hooks/guard.py` (срабатывает перед каждым вызовом инструмента). Отказ guard'а — это граница, а не баг: **не ищи обходной путь** (другая команда с тем же эффектом — нарушение). Запиши задачу `needs-user` с одним конкретным вопросом и переходи к следующей.

Вопросы человеку — только через `needs-user` на доске. Во всём остальном — рекомендуемое действие сразу, а не вопрос «можно?».

## 3. Цикл работы

1. **SYNC** — прочитай `ops/board.md` и материалы задачи; для торговых и ops-задач — `python -m src.ops status`.
2. **CLAIM** — статус задачи → `in-progress <агент> <ЧЧ:ММ>`, в заметках — файлы, которые будешь менять. Одна задача за раз.
3. **DO** — минимальный законченный инкремент.
4. **VERIFY** — проверь критерий готовности из доски буквально. Нельзя проверить — задача не `done`.
5. **RECORD** — статус `done` + артефакт в заметках; найденные проблемы и идеи → новые строки доски (`ready` или `needs-user`); факты о поведении API → `insights/`.
6. **NEXT** — следующая готовая задача. Останавливайся, только когда готовых нет или всё оставшееся ждёт человека.

Две неудачные попытки подряд → `blocked` с причиной и гипотезой, дальше другая задача. `in-progress` без изменений дольше 3 часов считается брошенным: можно забрать, указав это в заметках.

## 4. Доска `ops/board.md`

- Колонки: `ID | Задача | Агент | Статус | Зависит от | Критерий готовности | Заметки`. Автопилот читает таблицу машинно — не меняй заголовки.
- Статусы (первое слово ячейки): `ready`, `in-progress`, `blocked`, `needs-user`, `scheduled <ISO-время>`, `done`.
- `scheduled 2026-09-24T10:30+05:00` становится готовой в указанное время. Регулярные проверки после выполнения переставляют себя на следующее время, а не закрываются.
- `needs-user`: в заметках один вопрос, варианты и рекомендация. Работа над остальными задачами продолжается.
- Выполненные задачи старше суток переноси в раздел «Архив».

## 5. Параллельная работа

- Перед правкой файла проверь, не менялся ли он за последние 10 минут (`Get-Item <файл> | Select LastWriteTime`). Если менялся — перечитай и правь точечно; не перезаписывай целиком файлы, которые трогал другой агент.
- Claim задачи — это claim её файлов. Файл из чужой активной задачи не трогай: создай задачу-зависимость.
- Не создавай параллельные реализации того, что уже есть (см. §6). Нужен новый модуль — сначала проверь карту.

| `src/live_policy.py`, `src/live_preflight.py`, `src/live_runner.py` | Live-карман: окно и карман, предстартовая проверка (только чтение), runner рукава DCA (фоном — `ops\live.ps1`) |

| Что | Команда |
| --- | --- |
| Все unit-тесты (без сети) | `.venv\Scripts\python.exe -m unittest discover -s tests -t .` |
| Самотесты модулей | `python -m src.risk_selftest`, `src.order_router_selftest`, `src.dca_selftest` |
| Smoke-тест demo | `python -m src.smoke_test` |
| Движок фоном | `ops\engine.ps1 start` / `status` / `stop` |
| Риск и метрики | `python -m src.ops status` |
| Аварийная остановка торговли | `python -m src.ops kill "причина"` |
| Биржа (только demo) | `okx --demo <module> <action> …`, скиллы в `.agents/skills/` |
| Чьи ордера на счёте | `python -m src.order_audit [--hours 24]` — 0: норма, 1: есть ордер без метки агента или кода, 2: ошибка чтения |
| Реестр и новый clOrdId | `python -m src.order_owner`, `python -m src.order_owner new trd` |
| PnL по рукавам | `python -m src.pnl_ledger [--date YYYY-MM-DD] [--days 7] [--mode live]` — 0: норма, 1: есть предупреждения, 2: отчёт не построен |
| Бэктест | `python -m src.backtest baseline …` / `run …` (публичные свечи OKX, без ключей) |
| Памп-скан (без ключей) | `python -m src.pump_scanner --exclude <базы флота> [--json] [--no-journal]`; повтор: `--at 2026-09-24T09:47+05:00 --pairs OKB-USDT …` — 0: скан выполнен, 2: ошибка данных или сети |

**Метка владельца ордера (ORDER-OWNER-TAG).** Каждый ордер, algo-ордер и бот, которые ставит агент, получают clOrdId с префиксом владельца. Коды владельцев: OKX Trader `trd`, Pump Risk Taker `pmp`, Ops Sentinel `sen`, Insight Executor `iex`, Crypto Insight Hunter `hnt`.

- ID берётся командой `.venv\Scripts\python.exe -m src.order_owner new <код>`: 32 символа, только буквы и цифры, каждый раз новый.
- Обычный ордер: `okx --demo spot place … --clOrdId <id>`. Так же в `swap`, `futures` и `option place`.
- Algo-ордер: `okx --demo spot algo place … --clOrdId <id>` (CLI отправит его как `algoClOrdId`).
- Бот: `okx --demo bot grid create … --algoClOrdId <id>` и `bot dca create … --algoClOrdId <id>`.

Флага `--tag` у CLI нет: tag всегда `CLI` (у MCP — `MCP`), и по нему владельца не узнать. `--aiBuilderCode` для метки не используйте: он подменяет tag кодом атрибуции OKX. Код проекта ставит префиксы сам. `bot*` — движок и стратегии (реконсилятор считает их своими), `botl*` — только live-runner, `lt`/`rt`/`smk` — тесты. Ордер без clOrdId и tag на demo — это, вероятно, ручной ордер человека: для аудита это info, а не инцидент.

## 7. Готово — значит проверено

- **Код:** все unit-тесты и затронутые самотесты зелёные; поведение на бирже проверено на demo; документация и статус инсайта обновлены.
- **Исследование:** файл в `insights/` со статусом, ключевые факты подтверждены двумя источниками; открытые вопросы стали задачами на доске.
- **Торговая операция:** ID ордера/бота записаны, итоговое состояние проверено повторным запросом, запись в журнале.
- **Инцидент:** причина, принятые меры и что осталось — в `ops/incidents.md`.

## 8. Отчёт в конце хода

Коротко, по делу: **Сделано** (со ссылками на файлы) · **Проверено** (команда и результат) · **Доска** (что изменилось) · **Нужно решение человека** (только если есть `needs-user`).
